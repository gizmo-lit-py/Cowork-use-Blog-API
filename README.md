# Cowork-use-Blog-API

FastAPI / PostgreSQL / Docker を使用して構築した、ブログ投稿管理用のREST APIです。

ユーザー登録・ログイン、JWT認証、記事のCRUD、タグ管理、記事とタグの多対多リレーションを実装しています。  
API仕様はSwagger UIから確認でき、Docker Composeでローカル環境を再現できる構成にしています。

## 概要

このリポジトリは、FastAPIを用いたAPI開発、認証、DB設計、Dockerによる環境構築を学習・実装する目的で作成しました。

主な実装内容は以下です。

- ユーザー登録・ログイン
- JWTによる認証
- ブログ記事の作成・取得・更新・削除
- 自分の記事のみ更新・削除できる所有者チェック
- タグの作成・取得
- 記事とタグの多対多リレーション
- PostgreSQLを使用したデータ永続化
- Docker Composeによる開発環境構築
- Swagger UIによるAPI動作確認

- タグ一覧取得
- タグ作成
- 記事へのタグ紐付け

## APIエンドポイント

| メソッド | パス | 説明 | 認証 |
|---|---|---|---|
| POST | /auth/register | ユーザー登録 | 不要 |
| POST | /auth/login | ログイン | 不要 |
| GET | /posts/ | 記事一覧取得 | 不要 |
| GET | /posts/{post_id} | 記事詳細取得 | 不要 |
| POST | /posts/ | 記事作成 | 必要 |
| PUT | /posts/{post_id} | 記事更新 | 必要 |
| DELETE | /posts/{post_id} | 記事削除 | 必要 |
| GET | /tags/ | タグ一覧取得 | 不要 |
| POST | /tags/ | タグ作成 | 必要 |

## 設計で意識した点

### PostgreSQLを採用した理由

SQLiteだけで完結させず、実務でもよく使われるRDBMSを扱うためにPostgreSQLを採用しました。  
Docker ComposeでDBコンテナを起動し、アプリケーションから接続する構成にしています。

### JWT認証を採用した理由

APIとして利用しやすい認証方式を学ぶため、JWTによるトークン認証を採用しました。  
ログイン後に発行されたトークンを使って、記事作成・更新・削除などの認証が必要な処理を実行します。

### 所有者チェックを実装した理由

記事の更新・削除では、ログイン中のユーザーと記事の作成者を照合し、他ユーザーの記事を操作できないようにしています。  
APIにおける基本的な認可処理を意識して実装しました。

### 記事とタグを多対多で設計した理由

1つの記事に複数のタグを付けられ、同じタグを複数の記事で再利用できるようにするため、多対多リレーションで設計しました。  
中間テーブルを使い、記事とタグの関係を正規化しています。

### ルーターを分割した理由

認証、記事、タグの処理を分けることで、機能ごとの責務が分かりやすくなるようにしています。  
ファイルを分割することで、機能追加や修正時に対象箇所を追いやすい構成を意識しました。

## 起動方法

Docker Desktopを起動した状態で、以下のコマンドを実行します。

```bash
docker compose up --build
```

起動後、以下にアクセスします。

```text
http://localhost:8000/docs
```

Swagger UIからAPIの確認・実行ができます。

## 環境変数

このアプリケーションでは、DB接続情報やJWTの秘密鍵を環境変数で管理します。

例：

```env
DATABASE_URL=postgresql://user:password@db:5432/blogdb
SECRET_KEY=your-secret-key
POSTGRES_USER=user
POSTGRES_PASSWORD=password
POSTGRES_DB=blogdb
```

`.env` はローカル環境用のため、GitHubには含めない方針です。

## 開発時の補足

ローカル開発用のDBファイルや秘密鍵ファイル、環境変数ファイルはリポジトリに含めない方針です。  
`.env`、`*.db`、`*.pem` などは `.gitignore` の対象にしています。
